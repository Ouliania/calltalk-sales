# 🎙️ Регламент транскрибации и разбора записей встреч Call-Talk

Данный документ фиксирует **единственный стандартный способ** извлечения информации из любых аудио- и видеозаписей встреч (`.webm`, `.mp4`, `.m4a`, `.mp3`, `.mov`), чтобы исключить постоянные установки сторонних библиотек и разные подходы.

---

## 🛑 Главные запреты
1. **Категорически запрещено устанавливать новые библиотеки** (`pip install faster-whisper`, `mlx-whisper`, `speechrecognition`, `pydub` и т.д.). Всё необходимое ПО уже установлено в системе Mac!
2. **Запрещено использовать `--device mps` для Whisper:** В текущей связке PyTorch на Apple Silicon запуск Whisper с MPS выдает искаженные токены. На CPU модель `base` работает стабильно, качественно и транскрибирует 40-минутную встречу за ~2,5–3 минуты.
3. **Запрещено подавать тяжелый видеофайл напрямую в транскрибатор:** Видеофайлы весят сотни мегабайт. Сначала за 3 секунды через `ffmpeg` извлекается сжатое моно-аудио.

---

## ⚙️ Системный стек (уже установлен)
- **Утилита извлечения аудио:** `/opt/homebrew/bin/ffmpeg`
- **Движок транскрибации:** `/opt/homebrew/bin/whisper` (Python 3.12)
- **Локальная модель:** `base` (кэш в `~/.cache/whisper/base.pt`)

---

## 🚀 Единый способ запуска (1 команда)

В корне проекта Call-Talk создан исполняемый скрипт:
```bash
./transcribe_meeting.sh "/путь/к/файлу/записи"
```

### Что делает скрипт под капотом:
1. **Шаг 1 (2–4 сек):** Конвертирует видео/аудио в легковесный mono MP3 (16 kHz, 64 kbps):
   ```bash
   /opt/homebrew/bin/ffmpeg -y -i "$INPUT_FILE" -vn -ar 16000 -ac 1 -c:a libmp3lame -b:a 64k /tmp/audio.mp3 -loglevel error
   ```
2. **Шаг 2 (2–3 мин):** Транскрибирует на русском языке через CPU:
   ```bash
   /opt/homebrew/bin/whisper /tmp/audio.mp3 --model base --language ru --device cpu --output_dir "/Users/ulyana/CALL TALK/transcripts" --output_format txt
   ```
3. **Результат:** Сохраняет готовый текстовый файл `transcripts/<имя_файла>.txt`.

## 📋 Стандартный протокол отчета по встрече
Каждый раз после транскрибации записи встречи с клиентом ассистент формирует структурированный отчет:
1. **Паспорт клиента и контекст:**
   - Компания, сфера, ЛПР со стороны клиента, кто присутствовал.
   - Текущая ситуация в лидогенерации / продажах клиента.
2. **Подробный разбор целевых лидов клиента (Кто их клиенты и почему):**
   - Точный профиль их идеального клиента (ICP), сегменты рынка.
   - Кто принимает решение (должности).
   - Чек сделки, цикл сделки, LTV.
   - Почему именно эти сегменты и почему у них сейчас проблема с выходом на них.
3. **Озвученные боли, страхи и опыт клиента:**
   - Предыдущий негативный опыт (спам, претензии 152-ФЗ, слитые базы, холодные звонки).
   - Опасения по поводу репутации домена и юридических рисков.
4. **Обсужденные условия и позиция по офферу Call-Talk:**
   - Формат работы (MQL / SQL до встречи).
   - Объем базы, фикс, оплата за результат.
5. **Договоренности и следующие шаги:**
   - Что обещали прислать мы (КП, расчет, договор).
   - Что должен предоставить клиент (бриф, образец ЦА, доступ).
   - Сроки и дата следующего контакта.
