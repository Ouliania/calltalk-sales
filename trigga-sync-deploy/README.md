# 🚀 Trigga <-> OkoCRM Bi-directional Sync Daemon

Автоматический сервис (демон) двусторонней интеграции между сервисом холодных email-рассылок **Trigga** и **OkoCRM**.

---

## 📌 Что делает этот сервис

1. **Забирает входящие ответы из Trigga API:**
   - Читает тред-ответы из `/inbox/threads/` (входящие письма с ответами лидов).
   - *Примечание:* писем прогрева (ботов) в Trigga Inbox нет — сервис Trigga автоматически исключает прогревочный трафик из API инбокса.

2. **Интеллектуальная фильтрация:**
   - **Автоответы:** автоматически отсекает сообщения автоответчиков (*«В отпуске»*, *«Out of office»*, автоуведомления почтовых серверов Mailer-Daemon).
   - **Плоские отказы:** отсекает категорические «не актуально» и «отпишитесь».
   - **Отложенный интерес сохраняется:** если в письме есть триггеры отложенного контакта (*«сейчас не актуально, напишите через полгода»*, *«вернемся к вопросу весной»* и т.п.) — сделка **создается**, чтобы менеджер взял контакт в работу.

3. **Защита от дублей (Deduplication):**
   - Проверяет локальное состояние (`trigga_sync_state.json`).
   - Дополнительно проверяет наличие контакта и открытых сделок в OkoCRM по email перед созданием.
   - Дубликаты сделок исключены.

4. **Поочередное распределение 50/50 (Round-Robin):**
   - Распределяет новые сделки строго по очереди между менеджерами:
     - **Андрей** (`28418`, `andrey.s@calltalk.ru`)
     - **Леонид** (`28419`, `leonid.g@calltalk.ru`)
   - Указатель очереди сохраняется в состоянии и не сбивается при перезапуске.

5. **Создание сущностей в OkoCRM:**
   - **Сделка** в воронке *«B2B лидогенерация»* (ID: `30895`) на этапе *«Лид с Trigga»* (ID: `149636`).
   - Источник сделки: *«Email»* (ID: `78389`).
   - **Контакт** (имя, email, телефон при наличии).
   - **Компания** (название компании или домен контакта).
   - **Внутреннее примечание (Note)** в таймлайне сделки с полным текстом входящего письма, датой и темой.
   - **Коллеги в копии (Cc / To):** если в ответе в копию поставили коллегу (например, ЛПР переслал письмо закупщику или партнеру), скрипт автоматически извлекает email коллеги, создает дополнительный контакт и привязывает его к сделке.

6. **Двусторонняя обратная связь (OkoCRM ➔ Trigga):**
   - Если менеджер в CRM переводит сделку на этап **«Первичный контакт»** (или дальше по воронке), скрипт находит лид в Trigga и переводит его статус в `interested` («Интересно»).
   - Если менеджер закрывает сделку с причиной **«Trigga черный список»** (ID: `58924`), скрипт автоматически добавляет лид в черный список Trigga (`/blacklist/leads/`) и выставляет статус `not_interested`.

## 🛠 Требования к серверу

- **Операционная система:** Любой Linux (Ubuntu 20.04/22.04/24.04, Debian 11/12, CentOS, Rocky Linux, macOS, etc.).
- **Node.js:** Версия **18.0.0** или новее (`node -v`).
- **Зависимости npm:** **0 (ноль)!**
  - Скрипт написан на нативном чистом Node.js (`https`, `fs`, `path`).
  - Команду `npm install` выполнять **не требуется**.

## ⚙️ Настройка (.env)

Файл `.env` уже преднастроен боевыми ключами, но при необходимости параметры можно переопределить:

```env
# Токен Trigga (Settings -> API)
TRIGGA_API_KEY=TRIGGA_API_KEY_PLACEHOLDER
TRIGGA_BASE_URL=https://api.trigga.ru/api/public/v1

# OkoCRM MCP API (JSON-RPC 2.0 Bearer Token)
OKOCRM_API_TOKEN=OKOCRM_TOKEN_PLACEHOLDER
OKOCRM_MCP_URL=https://mcp.okocrm.com/crm

# ID воронки и названия сущностей
OKOCRM_PIPELINE_ID=30895
OKOCRM_STAGE_NAME=Лид с Trigga
OKOCRM_SOURCE_NAME=Email
OKOCRM_LOSS_REASON_NAME=Trigga черный список

# Ответственные менеджеры (50/50 Round-Robin)
MANAGER_1_ID=28418
MANAGER_2_ID=28419

# Интервал синхронизации (минуты)
SYNC_INTERVAL_MINUTES=5
```

## 🚀 Варианты развертывания на сервере

Скопируйте папку проекта на сервер (например, в `/opt/trigga-okocrm-sync`):

```bash
# Пример распаковки архива на сервере:
sudo mkdir -p /opt/trigga-okocrm-sync
sudo unzip trigga-okocrm-sync.zip -d /opt/trigga-okocrm-sync
cd /opt/trigga-okocrm-sync
```

### 🧪 Шаг 0. Тестовый прогон перед запуском (Dry Run)

Перед постоянным запуском убедитесь, что сервер имеет доступ к API Trigga и OkoCRM:

```bash
node trigga_okocrm_sync.js --dry-run
# или
npm run dry-run
```

Скрипт проверит подключение, выведет найденные этапы и статус синхронизации без создания новых сделок.

---

### Вариант 1: Запуск через PM2 (Рекомендуется)

PM2 автоматически перезапустит скрипт при сбое сервера или нехватке памяти.

1. Установите PM2 (если не установлен):
   ```bash
   npm install -g pm2
   ```

2. Запустите сервис:
   ```bash
   cd /opt/trigga-okocrm-sync
   pm2 start ecosystem.config.js
   ```

3. Сохраните процесс в автозагрузку ОС:
   ```bash
   pm2 save
   pm2 startup
   # Выполните команду, которую предложит pm2 startup
   ```

4. Полезные команды PM2:
   ```bash
   pm2 status                      # Проверить статус процесса
   pm2 logs trigga-okocrm-sync     # Смотреть логи в реальном времени
   pm2 restart trigga-okocrm-sync  # Перезапустить сервис
   pm2 stop trigga-okocrm-sync     # Остановить сервис
   ```

---

### Вариант 2: Запуск через systemd (Native Linux Service)

1. Отредактируйте путь к Node.js и каталогу в `trigga-sync.service`, если они отличаются (проверить путь к ноде: `which node`).

2. Скопируйте unit-файл в системную директорию:
   ```bash
   sudo cp /opt/trigga-okocrm-sync/trigga-sync.service /etc/systemd/system/
   ```

3. Перезагрузите конфигурацию systemd и активируйте сервис:
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable trigga-sync
   sudo systemctl start trigga-sync
   ```

4. Проверка статуса и логов:
   ```bash
   sudo systemctl status trigga-sync
   sudo journalctl -u trigga-sync -f
   ```

---

### Вариант 3: Запуск через Crontab (Периодический вызов)

Если вы предпочитаете не держать фоновый процесс, можно запускать одиночный прогон раз в 5 минут через cron:

```bash
crontab -e
```

Добавьте строку:
```cron
*/5 * * * * cd /opt/trigga-okocrm-sync && /usr/bin/node trigga_okocrm_sync.js >> /opt/trigga-okocrm-sync/sync.log 2>&1
```

## 📊 Мониторинг и логи

Скрипт ведет подробный журнал работы:
- `sync.log` — журнал всех итераций, найденных тредов, созданных контактов, сделок и обратных синхронизаций статусов.
- `error.log` — только ошибки (сбои сети, таймауты API).

Просмотр последних записей:
```bash
tail -f sync.log
```

## 🔒 Безопасность и ограничения API (Rate Limits)

- **OkoCRM API:** Работает по протоколу MCP JSON-RPC 2.0. При частых параллельных запросах OkoCRM отдает статус `429 Too Many Requests`. Скрипт содержит встроенный ограничитель (тротлинг 400 мс между вызовами) и механизм автоматического повтора с экспоненциальной задержкой (`retry backoff` 4 сек).
- **Trigga API:** Лимиты щедрые, скрипт запрашивает последние треды постранично.
- **Отказоустойчивость:** При временной недоступности сети демон не падает, а логирует предупреждение и повторяет попытку в следующем цикле (через 5 минут).
