# Call-Talk: эталон КП V4

**Источник:** `templates/kp-v3/CALL-TALK_Эталон_КП_9_слайдов_v3.html` из `main`, версия 05.11.2026.
V4 находится отдельно в `templates/kp-v4/`. V3 и старый шаблон `КП/` не изменены.

## Что изменилось

- 9 слайдов, исходные CSS, карточки, сетка и один кейс на слайде 4 сохранены.
- Слайд 5: «Для запуска используем 10 почтовых ящиков» по умолчанию; краткое описание подготовки персональных писем; две карточки сравнения.
- Слайды 6–7: убраны формульные сноски, уточнен смысл прибыли и окупаемости, заменены неизменяемые 15% и прогнозы на проверяемые параметры.
- Два режима одного макета: `terms` (2 и 4 месяца) и `qualification` (два формата квалификации). В обоих случаях два предложения на слайде 5 и связанные с ними слайды 6–7.
- Число ящиков, чек, конверсия и маржа берутся из конфигурации, а не задаются намертво.
- В V4 сохранены «3 касания» в карточках условий.
- **Нельзя** автоматически превращать шаблон V4 в предложение конкретному клиенту без проверки брифа, критериев квалификации, ставки и рыночных оценок.

## Сборка реального КП

Пошаговый регламент с источниками, выбором режима, расчетами, заполнением, трехуровневой проверкой и визуальным QA: **[СБОРКА_КП_V4.md](СБОРКА_КП_V4.md)**.

**До утверждения HTML V4 и merge PR #5 эта версия остается на ревью.** Не считать ее автоматически утвержденным эталоном для текущих клиентских КП.

## Проверка

```bash
pip install beautifulsoup4
python templates/kp-v4/validate_kp_v4.py --template templates/kp-v4/CALL-TALK_Эталон_КП_9_слайдов_v4.html
python -m unittest -v templates/kp-v4/test_validate_kp_v4.py
```

Для собственной проверки **исключительно на синтетических данных**:

```bash
python templates/kp-v4/generate_test_example.py --mode terms --output /tmp/kp-v4-test.html
python templates/kp-v4/validate_kp_v4.py --ready /tmp/kp-v4-test.html --config /tmp/kp-v4-test.json --client "Тестовая компания"

python templates/kp-v4/generate_test_example.py --mode qualification --boxes 20 --output /tmp/kp-v4-sql-test.html
python templates/kp-v4/validate_kp_v4.py --ready /tmp/kp-v4-sql-test.html --config /tmp/kp-v4-sql-test.json --client "Тестовая компания"
```

Режимы и коды проверки:
- `BLOCK` (exit code 1): некорректная сумма, структурное изменение, неразрешенный текст, служебные пометы, незаполненное поле, отсутствие JSON.
- `WARN` (exit code 0): например, 20/30 вместо 10 ящиков, другие конверсия/маржа, иные цены относительно стандартного тарифа, редакторская оговорка.
- `OK` (exit code 0): проверка по правилам прошла. WARN не снимается автоматически и требует согласования в переговорах.

Конфиг `--config`: объект с полями `client`, `mode` (`terms`/`qualification`), `boxes`, `touches`, `avg_check_rub`, `conversion`, `margin`, `variants`. Элемент `variants` содержит `months`, `monthly_fixed_rub`, `lead_price_rub`, `leads_calc`, `periods` (два периода, у каждого `contacts`, `rate_low`, `rate_high`). Ставки отклика указываются долями: 0.01 = 1%.

Два формата квалификации не подразумевают одинакового количества оплачиваемых результатов: задавайте `leads_calc` и ставки отклика отдельно, если это обосновано.

## Ограничения валидатора

Код подтверждает HTML-структуру, постоянные подписи, отсутствие служебных фраз, часть согласованности условий и арифметику. Он **не** устанавливает истинность рыночных оценок, реальность кейса, право использовать обещания, фактическую прибыль клиента, дизайн-переполнение в браузере и коммерческое согласование нестандартных условий. Каждый слайд дополнительно проверяется визуально при выпуске клиентского КП.

Ни один тестовый файл из `generate_test_example.py` нельзя отправлять клиенту: в нем синтетические значения и названия.
